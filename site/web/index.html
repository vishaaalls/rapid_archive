What this measures

Each step runs once to warm up, then the median of the chosen runs is shown. Every output is checked byte for byte against the original, and each library has to read the other's output.

The browser's built-in gzip is native code inside the browser, so for plain gzip it can match or beat WebAssembly, especially on Apple Silicon. That's why rapid_archive's async API (encodeBytesAsync, decodeBytesAsync) uses it on the web. WebAssembly still handles zip, which browsers can't do, plus custom compression levels and every synchronous call. At the same level, rapid_archive's gzip output is also about 9% smaller.

On Android, iOS and desktop there is no WebAssembly overhead and rapid_archive uses every CPU core, so native speedups are larger: up to 10× on an M4 MacBook.
